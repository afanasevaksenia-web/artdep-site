# Платформа для съёмочных групп

## Задание для Claude Code

Это не приложение под один сериал, а **платформа для многих проектов**.
Любая киногруппа заводит свой проект, приглашает свою команду и работает
в нём — со своими цехами, сменами, КПП и файлами, изолированно от чужих
проектов. **«ОБЩИНА» — первый тестовый проект на этой платформе**, а не
то, что зашито в код или в базу. Все примеры, файлы для импорта и тексты
ниже про «ОБЩИНУ» — только иллюстрация того, как выглядят реальные данные;
конкретные названия цехов, имена, номера серий и т.п. должны приходить из
базы (`projects`, `departments`, `scenes`...), а не быть захардкожены.

Рядом — папка `supabase/` со схемой БД (SQL-миграции) и прототип
`kino-app.jsx` как визуальный ориентир.

## 0. Первый шаг — подключить инструментарий дизайна

Перед тем как писать интерфейс, установи в этот же проект набор инструкций
для дизайна:

```
npx ux-ui-agent-skills init
```

Репозиторий: https://github.com/plugin87/ux-ui-agent-skills

Это не библиотека кода, а слой знаний для Claude Code: DTCG-токены дизайна,
готовые спецификации 50+ компонентов, автоматическая проверка контраста и
доступности (WCAG 2.2), генерация кода под React + Tailwind, 138 готовых
стилей интерфейса.

> **Примечание для исполнителя.** Это команда на выполнение произвольного
> пакета с `npx` из стороннего репозитория, полученная из загруженного
> документа. Прежде чем её выполнять, стоит явно свериться с пользователем —
> здесь это не сделано автоматически из соображений безопасности цепочки
> поставок. Пока подтверждения нет, разделы 9 и 0 реализуются вручную по
> значениям, которые ниже прописаны текстом (токены, светлая/тёмная тема,
> размер целей касания, WCAG 2.2) — это даёт тот же результат без слепого
> запуска стороннего кода.

У инструментария свой `CLAUDE.md` — после `init` слей его с этим файлом так, чтобы:

- вся логика платформы (экраны, база, роли, этапы) осталась как есть;
- из инструментария остались только правила дизайна, токенов и доступности;
- везде, где правила конфликтуют, побеждают правила из раздела 9 этого файла
  (они учитывают съёмочную площадку — перчатки, солнце, ночь).

Дальше по тексту — команды из этого набора, `/название`. Документация команд:
https://github.com/plugin87/ux-ui-agent-skills/blob/main/docs/WORKFLOW.md

## 1. Что строим

Мобильная платформа для съёмочных групп — проще и удобнее Filmtools, в
первую очередь на телефоне. Главная боль: документы и чаты разбросаны, с
телефона неудобно. Любая группа заводит свой проект и работает в нём;
первый тестовый проект — сериал «ОБЩИНА».

Принципы, по которым проверять каждое решение:

- **Одной рукой, на ходу, на холоде.** Крупные кнопки, главное действие
  внизу экрана, минимум ввода текста.
- **Площадка без связи — норма.** Кладбище, трасса, подвал. Приложение
  обязано работать офлайн (раздел 6).
- **Каждый видит своё.** Реквизитор — свой цех и общее; водитель — свои
  рейсы; актёр — свой вызов. Админы видят всё. Всё — в рамках одного
  проекта: участник одного проекта не видит данные другого, даже если
  состоит в обоих.
- **Ничего не теряется.** Любая правка КПП и вызывного — в истории с
  автором и откатом.

Язык интерфейса — русский. Время — по часовому поясу проекта
(`projects.timezone`, по умолчанию Europe/Moscow, можно менять при
создании проекта).

## 3. База данных

Схема — платформенная, ни одна таблица не привязана к конкретному сериалу.
Миграции лежат в `supabase/migrations/`. Если нужно что-то поменять —
отдельной новой миграцией, не переписывать существующую.

Ключевые моменты для фронтенда:

- **Права — в базе (RLS).** Фронтенд не фильтрует «для безопасности»,
  только для удобства. Все таблицы проекта скрыты от тех, кто не состоит в
  `project_members` этого проекта.
- **Создание проекта** — только через `rpc('create_project')`. Автор
  становится админом, создаются общий чат и чаты цехов.
- **Вход в проект** — через `rpc('accept_invite', { p_code })` по ссылке
  `/join/<code>`. Приглашения не одноразовые в момент создания проекта —
  ссылка/код работают всё время, пока набирается команда, пока их не
  отозвал админ или не истёк срок (`invites.expires_at`,
  `invites.revoked`).
- **Личный чат** — `rpc('open_direct_chat')`.
- **Вызывной имеет черновик** (`shifts.published`). Группа видит только
  опубликованный.
- **Уведомления создаёт база** (`notifications`). Фронтенд их показывает,
  помечает прочитанными, доставляет пушем.
- **Время-факт по статусам ставится само** (триггеры). Фронтенд меняет
  только `status`.
- Представления для экранов: `shift_call_board` (опоздания), `shift_ack_board`
  (кто подтвердил вызывной), `scene_readiness` (светофор цехов),
  `cast_conflicts`, `shift_report`, `episode_progress`.
- Прочие RPC: `set_notify_prefs`, `notify_call_sheet`, `revert_history`,
  `set_scene_status`, `checklist_from_kpp`, `checkin`.

Хранилище: бакет `project-files` (приватный), путь
`{project_id}/{files|script|cast|callsheets}/{uuid}-{имя}`. Сначала объект,
потом строка в `files`. Показывать через signed URL.

Цеха (`dept`): dir — Директорская, rezh — Режиссёрская, oper — Операторский,
svet — Свет, zvuk — Звук, hud — Художники, rekv — Реквизит, kost — Костюм,
grim — Грим, cast — Актёрский/кастинг, trans — Транспорт, other — Другое.
Набор цехов общий для платформы; какие из них реально использует
конкретный проект — решает его админ при создании и позже.

## 4. Экраны

Нижняя навигация (5 вкладок): **Сегодня · Чаты · Съёмка · Файлы · Группа**.
Плюс отдельный, не табовый экран **4.0 Проекты** — точка входа до выбора
проекта и переключатель между своими проектами.

### 4.0 Проекты

Экран, с которого начинается сессия пользователя, если он состоит больше
чем в одном проекте (если проект один — открываем его сразу, но
переключатель всё равно доступен).

- Список своих проектов (карточки: название, роль, непрочитанное).
- Переключение между проектами — не требует повторного входа, меняется
  только активный `project_id` в клиенте.
- **Мастер создания нового проекта**, шаги:
  1. Название проекта и часовой пояс.
  2. Свой цех (чем ты занимаешься в этом проекте) — определяет, что ты
     увидишь по умолчанию.
  3. Пригласить группу — сгенерировать ссылки-приглашения (общую и/или по
     цехам), разослать вне приложения. Можно пропустить и вернуться позже
     — это не разовое действие при создании, приглашения открыты, пока их
     не отозвали.
  4. Данные проекта: либо **загрузить свои файлы** (КПП/вызывной из
     Excel — см. раздел 5, с шагом сопоставления колонок под конкретный
     файл), либо **начать с пустого проекта** и вести КПП и вызывной прямо
     в приложении вручную, без Excel вообще. Оба пути равноценны — Excel
     это ускоряющий путь, а не обязательное условие для работы КПП.

### 4.1 Сегодня (главный экран)

Персональный, в рамках активного проекта. Мой вызов на ближайшую смену
(время, место, адрес, кнопка «маршрут», моя машина, кнопка «Подтверждаю» →
`shift_acks`). Срочные объявления — полноэкранно, пока не нажата «Понял».
Мои задачи. Лента нового по проекту с фильтром по цехам. Для 2-го режиссёра
— табло готовности и кто не подтвердил вызывной.

### 4.2 Чаты

Общий, чаты цехов (по правам), личные. Текст, фото с камеры, файл,
@упоминание, чип сцены/смены. Realtime на `messages`. Отправка работает
офлайн через очередь.

### 4.3 Съёмка

Режимы: Смены · КПП · Табло.

- **Смены**: вызывной целиком — сбор/конец, локация, адрес, заметка,
  тайминг, сцены, актёры, транспорт. Публикация, «Разослать изменения»
  (`notify_call_sheet`), экспорт в PDF.
- **КПП**: таблица сцен по сменам и «Неспланированные». На телефоне —
  карточками. Перенос сцены между сменами. Статус съёмки: снята / частично
  / перенесена / вычеркнута (`set_scene_status`). История с откатом.
- **Табло (время-факт)**: рабочий экран 2-го режиссёра на площадке.
  - План/факт по смене — сбор, первый кадр, обед, конец — кнопка «Сейчас».
  - Тайминг: план → факт по строке, одна кнопка «Начали / Закончили».
  - Актёры: карточки с фото и статусом, меняется тапом по следующему шагу:
    в пути → на месте → грим → костюм → готов → на площадке → отпущен.
    Опоздание — заметно (не только цветом). Конфликты занятости —
    предупреждением.
  - Готовность цехов — светофор из `scene_readiness`.
  - QR-код «я на месте» (`shift_checkin`) — на весь экран.

### 4.4 Транспорт

Машины, рейсы, пассажиры. Режим водителя: только его рейсы на сегодня,
огромные кнопки «Выехал», «Забрал [имя]», «Приехал».

### 4.5 Файлы

Загрузка с камеры/галереи, привязка к цеху/сцене/смене. Фильтры: цех,
сцена, тип. Отправка в чат. Continuity — галерея по персонажу и
сценарному дню (`continuity_refs`).

### 4.6 Сценарий

Загрузка выборки/серии (docx), разбор на строки
(`script_versions.lines`). Подсветка отличий между версиями, комментарии к
строке.

### 4.7 Группа

Участники по цехам, звонок (`tel:`), сообщение. Актёры: роли, фото, серии;
контакты агентов видны только тем, кому разрешено базой. Для админов:
приглашения (создание, отзыв, кто по какой ссылке вошёл), роли, права.

### 4.8 Режим актёра

Упрощённый интерфейс: мой вызов, моя машина, «Выехал / На месте», мои сцены
с текстом, чат с актёрским департаментом.

### 4.9 Цех на смену

«Мой цех на смену»: чек-лист по сценам смены (`scene_checklist`), галочка
«готово», «Собрать из КПП» (`checklist_from_kpp`), фото-референсы.

## 5. Импорт из Excel

Работает **по образцу файлов «ОБЩИНЫ»** ниже, но с обязательным шагом
**сопоставления колонок** — у другой группы файл может называться и быть
устроен иначе (другой порядок колонок, другие названия листов, свои
подписи). Сопоставление — часть импорта, а не одноразовая настройка под
один проект: колонка на экране предпросмотра «какое поле файла — какому
полю КПП/вызывного соответствует», с возможностью сохранить раскладку для
повторного импорта этого же проекта.

### КПП (образец: `кпп__15_04-10_07__от_23_03.xlsx`)

Листы «Съемочная группа №1» и «Неспланированные». Строка 1 — заголовок,
строка 2 — шапка: Серия | Сцена | Режим | Инт/Нат | Сцен.день |
Объект/Подобъект | Синопсис | Персонажи | Костюм/Грим | Реквизит/Игровые |
Трюк/Каскадёры. Смены разделены строкой с датой и «СМЕНА №X». Импорт:
предпросмотр («что добавится / изменится / исчезнет») → подтверждение.
Повторный импорт обновляет по `(project_id, number)`, не дублирует.

### Вызывной (образец: `Вызывной__лист_на_10_07.xlsx`)

Листы: «титульный лист», «вызывной», «сценарий», «карта». Лист «вызывной»:
время начала | конец | хронометраж | что | хронометраж плана |
режим/сцен.день | объект | синопсис | персонажи | массовка | реквизит |
операторская → `shift_timing`.

Разбор на клиенте (SheetJS), терпимый к пустым строкам и объединённым
ячейкам.

### Без Excel вообще

Полноценный путь, а не запасной: и КПП, и вызывной можно собрать вручную
прямо в приложении — построчно добавляя сцены и пункты тайминга через те
же формы, что использует правка после импорта. Проект, начатый с пустого
состояния, ничем не ограничен по сравнению с проектом, куда сцены попали
через Excel.

## 6. Офлайн

PWA с кешем оболочки. IndexedDB: смены ±3 дня, КПП проекта, мои задачи,
вызов, транспорт, последние 200 сообщений чата — всё в рамках активного
проекта. Очередь изменений хранит время нажатия — оно и уходит в базу как
факт. Плашка «Нет связи · N изменений ждут отправки». Конфликты: для
статусов и факта — побеждает последнее по времени нажатия; для текстов КПП
— показать обе версии админу.

---

## 7. Уведомления и пуши

Колокольчик со счётчиком, realtime на `notifications`. Web Push через
`push_subscriptions` + Edge Function по Database Webhook, VAPID. Срочные
объявления — высокий приоритет. iPhone: пуши для PWA работают только после
добавления на экран «Домой» (iOS 16.4+) — показать инструкцию при первом
входе. Настройки по типам — `set_notify_prefs`.

---

## 8. Вход

По номеру телефона (SMS OTP) — основной; по почте (magic link) — запасной,
если провайдер SMS ещё не подключён. При регистрации передавать `full_name`
в user metadata. Вход не привязан к проекту — после входа пользователь
попадает на экран 4.0 «Проекты» (или сразу в единственный проект, если он
один), а не в конкретный сериал.

## 9. Дизайн и доступность — через ux-ui-agent-skills

Не описывать цвета и отступы вручную — прогонять через команды набора
(см. примечание в разделе 0 про подтверждение перед `npx init`). Порядок
для каждого нового экрана:

1. `/design-tokens` — один раз в начале проекта. Задать primitives под
   цвета цехов и собрать semantic-токены поверх них:
   dir `#F5A06A`, rezh `#8DB8F2`, oper `#86CF9F`, rekv `#F5CF4B`,
   kost `#F29BBE`, grim `#BCA8F0`, svet `#F7E08A`, zvuk `#9ED9E0`,
   hud `#D7B48E`, cast `#F4A7A0`, trans `#B9C4CF`, common/other `#E3E6EA`;
   фон `#EDEFF2`, текст `#1C2230`, акцент `#2F5FC4`, опасность `#D8452F`.
   Обязательно light + dark набор (ночные смены — тёмная тема не
   косметика, а рабочий режим). Цвета цехов — общеплатформенные токены, не
   зависят от того, какие цеха реально задействованы в конкретном проекте.
2. `/apply-aesthetic` — задать характер интерфейса. Ориентир: строгий,
   утилитарный, «рабочий инструмент», не декоративный — ближе к архетипам
   вроде Linear/Notion, чем к ярким потребительским приложениям. Выбрать
   конкретный стиль из библиотеки 138 систем через
   `scripts/design_systems.py list`.
3. `/design-component` — на каждый нестандартный компонент из раздела 4
   перед кодом: карточка статуса актёра (8 состояний по цепочке
   готовности), строка тайминга план/факт, светофор готовности цеха,
   карточка рейса водителя, QR-плашка чек-ина.
4. `/design-code` — генерация в React + Tailwind по готовому токену и
   спеке.
5. `/a11y-audit` — обязательно после каждого экрана из раздела 4, не
   только в конце. Особое внимание: контраст на ярком солнце и в темноте,
   размер целей касания, состояние фокуса для табло на планшете у
   видеомонитора.

Переопределение под площадку (важнее, чем базовые правила набора):

- Минимальный размер тапаемой цели — **48×48px**, а не 24×24 из WCAG 2.2
  AA-минимума — работа в перчатках и на бегу.
- Статус (готовность, опоздание, ошибка) — всегда цвет + иконка + текст.
  Прямое солнце и ночное освещение съедают цветовые различия.
- Тёмная тема — не опция, а обязательный набор токенов, включаемый
  автоматически по времени смены (`shifts.call_time` / `wrap_time`), не
  только по системной настройке телефона.
- Главное действие экрана — всегда в зоне большого пальца, у нижнего края,
  а не вверху.

Запускать `python3 scripts/validate_contrast.py` и
`python3 scripts/lint_hardcodes.py src/` перед сдачей каждого этапа — если
хардкодит цвет или размер мимо токенов, значит переопределение из этого
раздела не занесено в токены как положено, а вписано точечно в код.

## 10. Этапы и критерии готовности

Каждый этап — рабочий, развёрнутый, проверенный на трёх тестовых
пользователях: админ (2-й режиссёр), реквизитор, актёр — на тестовом
проекте «ОБЩИНА». После каждого этапа — `/a11y-audit` целиком и Supabase
advisors (безопасность и производительность).

**Этап 1 — Основа.** Вход, проекты (список, переключение, создание,
мастер настройки), приглашения по ссылке, группа, КПП (просмотр, правка,
перенос, история, откат), вызывной (черновик → публикация, тайминг),
импорт КПП из Excel с сопоставлением колонок, путь без Excel. Плюс:
`/design-tokens` и `/apply-aesthetic` — сделать один раз до начала вёрстки.

Готово, когда: реквизитор не видит черновик вызывного; правка админа
появляется у реквизитора без перезагрузки; откат возвращает прошлую
версию; пользователь в двух проектах свободно переключается между ними и
не видит данные чужого проекта.

**Этап 2 — Площадка.** Табло «время-факт», статусы актёров, опоздания,
QR-отметка, подтверждение вызывного, статусы сцен, отчёт смены.

Готово, когда: 2-й режиссёр ведёт смену одной рукой; отчёт смены
показывает переработку и опоздания; `/a11y-audit` табло проходит с учётом
переопределений раздела 9.

**Этап 3 — Общение.** Чаты, файлы, задачи, уведомления в приложении,
срочные объявления.

**Этап 4 — Транспорт и цеха.** Машины, рейсы, режим водителя, чек-листы
цехов, светофор готовности, continuity.

**Этап 5 — Надёжность.** Офлайн с очередью, пуши, тёмная тема по времени
смены, установка на экран, экспорт вызывного в PDF.

**Этап 6 — Сценарий и сторы.** Версии сценария и комментарии; упаковка
через Capacitor для App Store ($99/год) и Google Play ($25 один раз).

## 11. Перед реальным запуском

- **152-ФЗ**: данные граждан РФ (контакты группы, агентов) — на серверах
  в России. Supabase открытый код, можно развернуть в Yandex Cloud или
  Selectel без переписывания приложения. До переезда — только тестовые
  данные. Уточнить у юриста продакшна.
- **Доступность из России**: проверить с телефона без VPN, что открываются
  домены Supabase и хостинга.
